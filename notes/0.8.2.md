# hrdrhrdrhrdr 0.8.2

macOS release, build 37.

This update fixes the In-app Browser tools not reaching Pi when Pi uses pi-mcp-adapter.

## Pi with pi-mcp-adapter

- In 0.8.0 and 0.8.1, when Pi used pi-mcp-adapter, a Pi tab started from New Tab could not use the In-app Browser. Inside Pi, the `3rdr-browser` server was "not found", and after 20 seconds the sidebar showed `pi-mcp-readiness-unconfirmed`.
- Cause: when a Pi session starts, Pi runs each extension's start-up step one after another. The app's extension ran first and asked pi-mcp-adapter to connect the browser tools before the adapter's own start-up step had run. The adapter turned the request down, and the app's extension then withdrew the browser tools it had registered.
- This happened when extensions in `~/.pi/agent/extensions`, which Pi starts before installed packages such as pi-mcp-adapter, took a second or more to start. An extension that waits for a reply from herdr is one example.
- The app now waits until every extension has finished starting before it connects the browser tools through pi-mcp-adapter. Pi without pi-mcp-adapter is unchanged.
- Verified with Pi 1.4.0 and pi-mcp-adapter 7.0.0.
- Pi tabs already running keep the previous behavior. Start a new Pi tab to use the fix.

## Requirements

Universal macOS app for Apple silicon and Intel; macOS 26.6.2 or newer. In-app Browser requires Apple silicon. Experimental features remain opt-in.
