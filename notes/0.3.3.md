# Shepherd 0.3.3

macOS release, build 27. Includes the updates implemented since 0.3.2.

In short: ⌘W closes the selected tab or pane instead of the window. A click in the terminal opens a file's preview only for an OSC 8 link. The sidebar puts Done agents above Working ones. The new tab launcher accepts any Pi 1.x. An experimental setting pastes the paths of files dropped on a terminal.

## Shortcuts that changed

- **⌘W** is Close Tab with Group by Tab on, and Close Pane with it off. It closes the selected tab or pane after the same confirmation the sidebar's context menu asks for. It used to close Shepherd's window and every terminal in it.
- Close Window stays in the File menu, without a shortcut.
- ⌘W is unavailable while nothing is selected, and while the new tab launcher, Settings, Go to Agent or Pane…, an expanded preview or an alert is over the terminal.

## Links in the terminal

- A click opens a file's preview only for an OSC 8 link to the file, such as `ls --hyperlink` prints. In 0.3.2, a click on plain text that looked like a path also opened a preview.
- Plain text is not a file link, even when it looks like a path, a `path:line` location or a `file://` URL. A click on such text goes to the program in the pane, with or without Command. Holding Command may still underline it, but clicking it opens no preview.
- `http` and `https` URLs are still recognized in plain text and open in a new tab of that pane's browser, as in 0.3.2.
- Korean, Japanese or Chinese text written straight after a URL, as in `…/pull/16048에서`, is no longer taken as part of the URL. A click on the URL opens the URL alone, and a click on that text opens nothing.

## Sidebar

- Each workspace's rows are ordered Blocked, Done, Working, Idle, then agents whose status herdr can't tell, then panes with no agent. Done used to come last of the agents. Within a status, the agent that reached it most recently comes first.
- With Group by Tab, tabs follow the same order instead of herdr's. A tab is placed by its highest-ranked agent, and its row shows that agent's status. So a tab with a Working and a Done agent now shows Done. A tab with no agent goes last.
- When a Done pane stays selected for half a second, Shepherd tells herdr that the pane's tab has been seen. With Group by Tab, the same happens when a tab with a Done agent stays selected. herdr then reports every finished agent in that tab as Idle. Before, an agent that had been read in Shepherd stayed Done until it was given more work.
- This happens only while Shepherd's window is active. Rows passed over with the arrow keys don't count. If herdr's own interface is open in a terminal, it switches to that tab. The focused pane in the tab does not change.

## Settings

- The main page of Settings ends with a Version row, such as `0.3.3 (27)`. The text can be selected and copied. The Updates section no longer shows the version.

## Terminal File Drop (experimental)

- Settings → Experimental Features has a new Terminal File Drop (Experimental) setting. It is OFF by default. While it is off, a terminal takes no drops, as before.
- With it on, dropping files from Finder on a terminal pastes their paths, escaped and separated by spaces, as one paste. Claude Code attaches an image when a pasted path names one.
- A pane of this Mac's own herdr gets the paths as they are, for files and folders alike.
- For a pane on another machine, PNG, JPEG, GIF and WebP images are uploaded first, to `~/.cache/shepherd/drops/` on that machine, and their paths there are pasted once the uploads finish. A drop takes up to 20 images of at most 16 MiB each. Other files and folders are skipped.
- A banner along the bottom of the pane shows the upload's progress, with Cancel, and names what was skipped or failed. Leaving the pane cancels the upload, and nothing is pasted then. A pane takes one drop at a time.
- Uploads go over SSH, only to a machine whose host key is already known. Uploaded images are removed after a day, the next time files are dropped on that machine.

## Pi

- The new tab launcher accepts any Pi 1.x release (`^1.0.0`), not only Pi 1.1.0. Pi 2.x, 0.x and pre-release versions are still refused. Pi still needs Node 22.19.0 or newer.
- Shepherd was tested with Pi 1.1.0 and 1.2.0. With 1.2.0, the tests started Pi with Shepherd's browser tools but did not yet operate a page.

## Fixes

- A second Shepherd started while one was running replaced the running one's browser agent token, and every agent launched after that got 401 on each browser call. The token file is now written only after the browser listener has taken its port, and its name includes that port (`agent-token-<port>`).
- Turning the experimental browser off and on, or applying the same port again in Settings, no longer makes agent launches fail with `browser-listener-not-ready`. Terminals opened while the browser was on used to keep the browser's port in use after the browser stopped, so the browser could not start again on that port.
- When a Claude Code that Shepherd launched starts another Claude Code or Codex with `herdr agent start`, the new agent now gets Shepherd's browser even if its herdr pane ID has letters, such as `wE:p1C`. Only pane IDs made of digits worked before.
- After Shepherd restarts, an agent that it launched before the restart no longer makes Settings → Experimental Features → Diagnostics show "Shepherd agent runtime rejected the operation (duplicate-registration).". Shepherd used to check that agent again about every two seconds, running node and the agent's `--version` and `--help` each time. It no longer does. That agent's browser status stays unknown, as before.

## Internal

- A debug build asks for browser agent port 9334 until a port is saved in Settings, so that it can run beside a released Shepherd. A release build asks for 9333 as before.

## Compatibility and scope

- Universal macOS app (Apple silicon and Intel); macOS 26.6.2 or newer.
- The experimental browser remains OFF by default. Its scope is unchanged from 0.3.2, apart from the Pi versions it accepts.
- Terminal File Drop is experimental and OFF by default.
- The Markdown preview remains inert: nothing in a document is executed or fetched. The file preview's limits are unchanged from 0.3.2.

Checks made for this release: the usability tests pass on this source. The app is built, signed and notarized by the repository's release workflow on a GitHub-hosted runner. The checks do not operate the installed app's interface or go through an automatic update.
