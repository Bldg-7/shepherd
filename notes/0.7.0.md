# hrdrhrdrhrdr 0.7.0

macOS release, build 33.

This update adds opt-in, in-memory conversation capture for a compatible iPhone or iPad app, improves sidebar navigation, and fixes terminal input handling. The iPhone and iPad app is distributed separately; installing this macOS update does not update TestFlight.

## Sidebar and keyboard focus

- Clicking a pane in the sidebar gives its terminal the keyboard, including clicking a pane that is already selected. Clicking a tab returns to its last active pane, falling back to herdr's focused pane. Existing terminal connections are retained.
- Clicking a row ends title editing and moves an expanded file preview back beside the terminal. Search edits and status refreshes do not issue new focus requests.
- Drag group headers to reorder the sidebar's machine groups. The order is kept separately for each host. Groups fold temporarily during the drag and return to their previous state afterward.
- Pane rows show Claude Code's and Pi's logos, while keeping their names available to search, VoiceOver and tooltips.

## Conversations on iPhone and iPad

- Settings → iPhone and iPad has **Show Conversations on iPhone and iPad**, off by default and changeable only while connected to This Mac. It enables a local model-API proxy and a background conversation collection process.
- Supported newly launched local agents can have their API requests routed through the proxy. Captured messages are kept in bounded memory, not written as a durable conversation archive. Existing transcript files are not read. This does not record a microphone, the screen or terminal output.
- A compatible paired iPhone or iPad can read and subscribe to conversations through its existing authenticated SSH connection. Arbitrary SSH hosts and nested herdr machines are not added to this capture scope.
- The reader preserves visible history across recognized compaction boundaries and marks missing, incomplete or truncated content rather than inventing it. Verified subagent metadata can show observed children and their final answers; unknown parent relationships remain unknown.
- Main requests, compaction, background warming and auxiliary requests are distinguished only when their identities and provider contracts are verified. Pi capture is qualified for the tested 1.3.0 and 1.4.0 contracts. Headless or inherited child launches do not gain a parent's capture or browser identity.
- Restarting the conversation collection process or reaching its memory limits can remove history. Enabling the setting does not recover earlier conversations. The mobile app can use its Screen view when captured content is unavailable.

## Terminal and launch fixes

- Ctrl+B now reaches the pane's program instead of being consumed as herdr's attach prefix. Compatibility handling distinguishes older herdr versions, encoded keyboard protocols and bracketed paste.
- Terminal SSH attaches disable SSH's own escape processing, preventing escape sequences such as `~.` from unexpectedly ending the attach. Shared SSH settings are unchanged.
- Pi launched from New Tab waits for its new shell's startup to settle before taking its working directory, reducing intermittent launch failures.
- File preview restoration uses visible-row anchors instead of estimated lazy content heights, and explicit user navigation takes precedence over restoration.

## Pairing and scope

- Adding a herdr machine or pairing an iPhone or iPad is available only while the window is connected to This Mac. Existing devices remain visible and removable elsewhere. Reconnect and removal of herdr machines are unchanged.
- QR pairing privacy disclosures now describe the data carried by the code, the temporary listener, approval, and SSH authorization.
- Universal macOS app for Apple silicon and Intel; macOS 26.6.2 or newer. In-app Browser requires Apple silicon. Experimental features remain opt-in.
- Markdown remains inert: documents do not execute HTML or download embedded images. Browser/credential approval is separate from conversation metadata and is not inherited by child agents.
