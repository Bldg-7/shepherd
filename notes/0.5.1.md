# hrdrhrdrhrdr 0.5.1

macOS release, build 30. Fixes a crash in 0.5.0, and includes the other updates implemented since 0.5.0.

In short: starting hrdrhrdrhrdr Browser no longer quits the app. The new tab launcher closes as soon as an agent's start command is in its new pane, instead of waiting until the agent is ready.

## Fixes

- In 0.5.0, starting hrdrhrdrhrdr Browser quit the whole app, terminals included. The browser engine looked for its helper processes under the app's new name. The helpers are still called Shepherd Helper, so the engine found none, could not start its GPU process, and quit. It now finds Shepherd Helper again.

## New tab launcher

- The new tab launcher offers Claude Code, Codex and Pi when hrdrhrdrhrdr Browser is on. Launching one of them now closes the launcher as soon as the agent's start command is in the new pane. Before, the launcher stayed up with its spinner until the agent was ready, a few seconds after the agent's screen had appeared.
- While hrdrhrdrhrdr waits for the agent to be ready, the sidebar shows "Waiting for agent readiness…", as before. A failure after the launcher has closed shows only in the sidebar: a red globe with the reason in its tooltip, and "Agent launch failed" on the tab's row. A failure before the start command, such as a missing CLI, still shows in the launcher.
- A prompt sent right after the launch no longer makes the launch fail. An agent that is already working counts as ready.
- A launch that ends late no longer closes a launcher opened again in the meantime.
- In a new workspace, the tab has its name before the launcher closes.

## Known issue

- The browser engine keeps the key it encrypts cookies with in a Keychain item named "Chromium Safe Storage". If another app made an item with that name first, starting hrdrhrdrhrdr Browser shows a Keychain prompt for it.
- Allow lets the browser read its saved logins this time, and the prompt comes back the next time the browser starts. Always Allow does the same and stops the prompt. Deny leaves the browser unable to read its saved logins, and it drops them.

## Compatibility and scope

- The Macs hrdrhrdrhrdr runs on, and the scope of its experimental features, are unchanged from 0.5.0.

Checks made for this release: the tests for the launcher changes pass on the source this release is built from. The browser fix was checked against the browser engine's source and against the helper processes in the built app. The app is built, signed and notarized by the repository's release workflow on a GitHub-hosted runner. No check opened hrdrhrdrhrdr Browser in the installed app or installed this release through an automatic update.
