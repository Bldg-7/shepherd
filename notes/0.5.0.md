# hrdrhrdrhrdr 0.5.0

macOS release, build 29. Includes the updates implemented since 0.4.0.

**Shepherd is now called hrdrhrdrhrdr.** It is the same app: updating from 0.4.0 keeps your machines, settings, Keychain items and browser data. The update window in 0.4.0 still calls this update "Shepherd 0.5.0", because it shows the name of the app that is running.

In short: besides the new name, a link clicked in a terminal opens in hrdrhrdrhrdr Browser or in the default browser, whichever the new Open links in setting names, and ⌘-click opens it in the other one. The file preview stays with the pane or tab it was opened from. Choosing Pi no longer fails when the shell finds another `pi` first on PATH.

## New name

- The app is called hrdrhrdrhrdr wherever it shows its name: the menu bar, the window's title, Settings and its explanations, and the update windows. The Korean and Japanese text says hrdrhrdrhrdr too. Shepherd Browser is now hrdrhrdrhrdr Browser, and the sidebar menu's Resume with Shepherd Browser is now Resume with hrdrhrdrhrdr Browser.
- The disk image is now `hrdrhrdrhrdr.dmg`, with `hrdrhrdrhrdr.app` in it. The update archive is `hrdrhrdrhrdr-0.5.0.zip`.
- The bundle identifier stays `com.bldg-7.shepherd`. So the machines and settings, the SSH keys and passwords in the Keychain, the Application Support folder (`~/Library/Application Support/com.bldg-7.shepherd`) with the browser's data, and automatic updates all carry over.
- Updating keeps the app at its current path and file name: `/Applications/Shepherd.app` stays `/Applications/Shepherd.app`, and the app in it is hrdrhrdrhrdr.
- If you install `hrdrhrdrhrdr.dmg` on a Mac that has Shepherd 0.4.0, delete `Shepherd.app` from Applications afterwards, so that only one copy of the app is on the Mac.
- Names given to agents stay as they were: the `shepherd-browser` skill and MCP server. The repository stays at `Bldg-7/shepherd`. The browser engine's helper processes are still called Shepherd Helper.

## Opening links

- An http or https link clicked in a terminal now opens in the clicked pane's hrdrhrdrhrdr Browser or in the Mac's default browser. Before, it could open only in hrdrhrdrhrdr Browser, and with the browser off or unavailable only an alert was shown.
- Settings → Experimental Features has a new setting, Open links in, on the hrdrhrdrhrdr Browser card: Ask first, hrdrhrdrhrdr Browser or Default Browser. The setting starts as Ask first.
- With Ask first, clicking a link shows a popover at the link with Open in hrdrhrdrhrdr Browser and Open in Default Browser. Its "Don't ask again" is on at first; with it on, the browser you choose becomes the setting. Return opens the link in hrdrhrdrhrdr Browser. Escape, or a click outside, opens nothing.
- ⌘-click opens a link in the other browser: in the default browser when the setting is hrdrhrdrhrdr Browser, and in hrdrhrdrhrdr Browser when it is Default Browser. With Ask first, ⌘-click opens the default browser without asking.
- With hrdrhrdrhrdr Browser off, or unavailable on this Mac, every link opens in the default browser. When the setting is hrdrhrdrhrdr Browser, a notice at the bottom of the terminal says why the link opened in the default browser. A link never turns the browser on.
- The browser's ⋯ menu has Open in Default Browser, which opens the page shown there. The tab stays as it is.

## File preview

- The file preview stays with the pane or tab it was opened from. Selecting another one and coming back shows the same file in the same view and at the same place, without reading it again. With the browser on, a preview covers the browser only in its own pane.
- Before, selecting another pane or tab closed the preview, and opening a file turned the browser column off in every pane.
- Closing the preview and opening it again with Show Preview reads the file again, as Retry does.
- In a pane that shows a preview, Show Browser closes the preview but keeps its file, so Show Preview brings it back.
- Selecting another pane or tab while the preview is expanded ends the expansion. Coming back shows the preview at the side panel's size.
- Previews stay when you switch to another machine. A pane's preview is dropped when herdr no longer lists the pane, or when its machine is removed, or edited so that its connection changes (host, port, user, herdr session or credentials). Previews are kept only while hrdrhrdrhrdr is running.

## Fixes

- With hrdrhrdrhrdr Browser on, choosing Pi in the new tab launcher failed when the shell's startup files, such as `~/.zshrc`, put a folder with another `pi` ahead of the session's own `pi` on PATH, as a bun install of Pi does. The shell ran that Pi instead of the session's own, Pi showed `Failed to load extension … pi-host-bridge-unavailable`, and the launch failed about 20 seconds later. hrdrhrdrhrdr now types the session's `pi` by its full path, so PATH no longer decides which one runs.

## Internal

- A Pi launched from the new tab launcher is typed into the pane instead of started with herdr's `agent.start`. herdr still detects Pi in the pane, but no longer gives it a `pi-<id>` agent name, which herdr gives only to agents it starts itself. The launch is ready once herdr reports Pi idle in that pane.
- The native Pi test runs with a `~/.zshrc` that puts another Pi ahead on PATH, and passes with Pi 1.3.0 and herdr 0.9.1.
- The herdr lifecycle tests' helper is now in the repository, so a fresh checkout can run them.
- The bundle identifier, the source folder, the Xcode target and scheme, and the `SHEPHERD_*` environment variables keep the name Shepherd.

## Compatibility and scope

- Universal macOS app (Apple silicon and Intel); macOS 26.6.2 or newer. hrdrhrdrhrdr Browser needs Apple silicon: the embedded browser engine (CEF) is built for Apple silicon only. On an Intel Mac, hrdrhrdrhrdr runs without it, and links open in the default browser.
- hrdrhrdrhrdr Browser and Terminal File Drop remain experimental and OFF by default. The Open links in setting is shown even with the browser off.
- Pi launching keeps its scope: Pi 1.x, fresh local sessions, with hrdrhrdrhrdr Browser on.
- The Markdown preview remains inert: nothing in a document is executed or fetched. The file preview's limits are unchanged from 0.4.0.
