# hrdrhrdrhrdr 0.6.0

macOS release, build 32. Includes the updates implemented since 0.5.1, among them the fixes prepared for 0.5.2, which was not released.

In short: the hrdrhrdrhrdr app for iPhone and iPad can add this Mac by scanning a QR code that Settings shows. hrdrhrdrhrdr can save other computers in herdr as herdr machines, and remove them. A plain drag selects text in a shell or Claude Code pane, and ⇧-drag in any pane. A click on a web link in a terminal opens it in the pane's In-app Browser, and ⌘-click in the default browser. The file preview has a table of contents for Markdown, ⌘F to search and a Reload button. hrdrhrdrhrdr Browser is now called In-app Browser. The names agents see for it change from `shepherd-browser` to `3rdr-browser`, so if you allowed its tools by name in Claude Code or Codex, add rules for the new names.

## New names

- hrdrhrdrhrdr Browser is now called In-app Browser wherever the app names it: the Experimental Features toggle and its explanation, Resume with In-app Browser in the sidebar's menu, and the notices that name the browser. The Korean and Japanese text use the English name too.
- The browser engine's helper processes, which Activity Monitor shows, are now called 3rdr Helper, 3rdr Helper (Alerts), 3rdr Helper (GPU), 3rdr Helper (Plugin) and 3rdr Helper (Renderer), instead of Shepherd Helper.
- Agents see the browser under new names. The MCP server and the skill are now `3rdr-browser`, and the Claude Code plugin is `3rdr`. Its tools are now `mcp__plugin_3rdr_3rdr-browser__*` in Claude Code and `mcp__3rdr_browser__*` in Codex and Pi. Before, they were `mcp__plugin_shepherd_shepherd-browser__*` and `mcp__shepherd_browser__*`.
- **If you allowed the browser's tools by name in Claude Code's or Codex's permission rules, add the same rules for the new names.** Rules for the old names no longer match.
- Agent sessions started before the update keep the old names until they end, and hrdrhrdrhrdr still recognizes them.
- Pi's status line shows `3rdr:` instead of `Shepherd:`. A new SSH key made in Add Machine has the comment `3rdr-<name>`. Files dropped on a pane of an SSH machine or a herdr machine, with Terminal File Drop on, go to `~/.cache/3rdr/drops` instead of `~/.cache/shepherd/drops`. Batches left in the old folder are removed once they are a day old, the next time a file is dropped on that machine.
- Unchanged: the app is still hrdrhrdrhrdr, in `hrdrhrdrhrdr.dmg`. The bundle identifier stays `com.bldg-7.shepherd`, so machines, settings, Keychain items and browser data carry over.

## iPhone and iPad

- Settings has a new page, iPhone and iPad, that lists the iPhones and iPads allowed to log in to this Mac and adds one by QR code for the hrdrhrdrhrdr app for iPhone and iPad. The device logs in over Remote Login (SSH) with a key from its Secure Enclave. After you compare a confirmation code and approve with Touch ID or your password, hrdrhrdrhrdr adds one line for the device to `~/.ssh/authorized_keys`. The line starts with `restrict,port-forwarding`: it turns off SSH's optional features, such as a terminal and agent forwarding, except port forwarding, which the device uses to reach herdr.
- Remote Login must be on, and hrdrhrdrhrdr doesn't turn it on. While it is on, this Mac accepts SSH logins from your network, as it would for any SSH client.
- You choose the address the code carries: the `.local` name, a private IPv4 address, or with Tailscale its IPv4 address or MagicDNS name. Codes are shown only when you ask. Each code can be used once and lasts two minutes, and a new code replaces it every two minutes. The Mac listens for devices only while codes are shown, for ten minutes at most. With the firewall on, macOS may ask once whether hrdrhrdrhrdr may accept incoming connections.
- A request whose device cancels or disconnects before you answer is closed on the Mac without adding anything.
- Removing a device from the list takes out its line from `authorized_keys`. A connection the device already has open stays until it ends.
- The iPhone and iPad app is being tested on TestFlight and is not yet on the App Store.

## herdr machines

- hrdrhrdrhrdr can add a herdr machine to a host's herdr, check one that fails to connect, and remove one. A herdr machine is a computer saved in herdr with `herdr machine add`. The host is the machine hrdrhrdrhrdr is connected to: This Mac, or an SSH machine added in Settings → Machines. This needs herdr 0.9.0 or later on the host. With an earlier herdr, the new tab launcher shows Add herdr Machine… greyed out and says why.
- Add: File → Add herdr Machine…, Add herdr Machine… in the host's group header menu, or the last row of the new tab launcher's Machine step. When no herdr machine is saved yet, the launcher skips that step; press Backspace while the Workspace step's field is empty to go back to it.
- Pick a Host alias from the host's `~/.ssh/config`, or type an SSH target, and name the new machine. hrdrhrdrhrdr first checks on the host that the host can sign in to the target the way herdr will. If the target's host key is new to the host, it shows the key's fingerprint, and adds the key to the host's `known_hosts` when you trust it. It never overwrites a key that has changed or been revoked.
- In three cases you have to answer at a terminal: herdr needs to install or update itself on the new machine; the target is reached through a jump host whose key the host doesn't know; or the sign-in asks you to log in in a browser. hrdrhrdrhrdr then opens a new tab on the host that runs `herdr machine add` there.
- A target that accepts only a password, or a password and a one-time code, can't be added: herdr signs in only with SSH keys or ssh-agent.
- Reconnect… in the group header menu of a herdr machine that fails to connect runs the checks again.
- Remove “name”… in a herdr machine's group header menu, or File → Remove herdr Machine “name”…, removes it from the host's herdr after you confirm. The herdr sessions running on that machine keep running, and its host key stays in the host's `known_hosts`.

## Opening links

- Clicking an http or https link in a terminal opens it in a new tab of the clicked pane's In-app Browser, the way clicking a file link opens its preview. ⌘-click opens it in the Mac's default browser.
- The Open links in setting, and the popover that asked where to open a link, are gone. If you had chosen Default Browser, a click now opens links in In-app Browser; ⌘-click opens them in the default browser.
- With In-app Browser off, links open in the default browser, without a notice. With it on but unable to run on this Mac, they open in the default browser, and a notice says why.
- A double or triple click on a link opens it once. Before, each click opened another tab.

## HTML files open in a browser

- Clicking a terminal link to an `.html` or `.htm` file on This Mac now opens the page in a browser instead of showing its source in the preview. With In-app Browser on, a click opens it in a new tab of the pane's In-app Browser, and ⌘-click opens it in your default browser, as for web links.
- With In-app Browser off, as it is by default, clicking such a link opens the file in your default browser.
- The default browser is the app that opens web links, even if `.html` files are set to open in an editor.
- While an agent is connected to the pane's In-app Browser, a click opens the file in your default browser, and a notice says why. When an agent connects, In-app Browser tabs that show files on your Mac become blank, so that the agent can't see them.
- Links to HTML files in panes of SSH machines and herdr machines still open in the preview, and the preview still shows HTML as source without running it.

## Selecting text in the terminal

- In a shell, or in Claude Code in its default mode, dragging in the terminal now selects text, and ⌘C copies it. Before, the drag went to herdr, which dropped it, and nothing was selected.
- ⇧-drag selects in every pane, Pi and Codex included, where a plain drag goes to the program. ⇧-drag also selects when it starts on a link. Before, a ⇧ selection disappeared as soon as the pane's output changed, and a drag that started on a link selected nothing.
- A selection now stays while the pane's output changes elsewhere on the screen. It ends when the text under it changes, and at a click, a key or a change of the window's size.
- ⇧-click on a link no longer opens it. It extends the selection, if there is one.
- Unchanged: in Pi and Codex a plain drag still goes to the program; the mouse wheel still scrolls herdr's scrollback; a click or ⌘-click on a link opens it as before.
- How: hrdrhrdrhrdr now starts its herdr attaches with herdr's mouse capture off, through a herdr configuration file of its own: `~/Library/Caches/com.bldg-7.shepherd/herdr-attach.toml` on this Mac, and `~/.cache/3rdr/herdr-attach.toml` on an SSH machine or herdr machine. Your `~/.config/herdr/config.toml` is not changed, and hrdrhrdrhrdr's attaches don't read it: settings the attach applies itself, such as `ui.mouse_scroll_lines` and custom notification sounds, are herdr's defaults in hrdrhrdrhrdr.

## Table of contents in Markdown previews

- A Markdown file in the preview shows a table of contents of its headings at the top right, on a Liquid Glass panel. It is there in the rendered view and in Source, whether the preview is beside the terminal or expanded.
- Click a heading to bring it to the top of the preview. The heading you are reading is highlighted, and a long list scrolls to keep it in view.
- The list button next to Source hides or shows it. Hiding it applies to that preview only, and every Markdown file you open starts with it shown. A file with no headings has the button dimmed.
- Headings inside fenced code are not listed. A heading's name is its text without Markdown: bold, code and links show as plain text.

## Find in the file preview

- Press ⌘F in the file preview to search the text it shows. A find bar opens at the top of the preview and finds as you type, ignoring case.
- A rendered Markdown file is searched in the text you see, including code, tables and frontmatter. In Source, and in other text files, the lines are searched as written.
- Every match is highlighted, and the current one stands out. The bar shows where you are, such as 3 / 17, or No Results.
- A new search starts from the first block or line on screen. Return or ⌘G goes to the next match, and ⇧Return or ⇧⌘G to the previous one. The preview scrolls to it.
- Esc or the close button closes the find bar. Each pane's preview keeps its search until its file is opened again.
- A click in the preview now gives it the keyboard, so that ⌘F reaches it. After that click, typing goes to the preview, not the terminal; click the terminal to type there. ⌘F in the terminal still goes to the terminal. With the find bar closed, Esc closes the preview.

## Reload in the file preview

- The file preview's header has a Reload button (↻), left of the expand button; in a Markdown file it comes after Source and the table of contents button. ⌘R does the same while the preview has the keyboard. While the terminal has the keyboard, ⌘R goes to the terminal as before. There is no menu item for it.
- Reload reads the same file again from the same machine. A remote file is read over a new SFTP connection with the saved credential, as when it was opened.
- What you were looking at stays: the rendered view or Source, the scroll position, the line a `path:line` link highlighted, whether the table of contents is shown, and the find bar with its search. The find bar counts its matches again in the new text, and ⌘G or Return then goes to the first match from the part of the file on screen. If the file is now shorter than where you were, the preview stops at its end.
- While the file is read, the old text stays on screen and a small spinner takes the button's place. The button is disabled until the read ends, so pressing it again doesn't start a second read.
- If the read fails, for example because the file was deleted, the preview shows why, with Retry. Retry now works like Reload: when the file can be read again, it comes back in the same view at the same place.
- The preview never reloads by itself, and selecting its pane again does not reload it. Closing the preview and showing it again with Show Preview, or opening the file again from a link, still starts over.

## Pasting a pane's or tab's ID

- Drag a pane or a tab from the sidebar onto a terminal to paste its herdr ID there, for example `w1:p4` or `w1:t2`, followed by a space. No Return is pressed, and the keyboard stays where it was. Use it to tell an agent, or the `herdr` command line, which pane or tab you mean.
- Every connected terminal takes the drop, whether or not an agent runs in it, and with Terminal File Drop on or off. A terminal takes only panes and tabs from the same herdr as its own pane: a pane of a herdr machine can't be dropped on a pane of the host, and a pane of the host can't be dropped on a pane of a herdr machine.
- While a drop would be taken, the terminal shows an accent-colored border. Dropped into another app, a row gives the ID alone.

## Pane names reach the agent's session

- Renaming a pane (Rename Pane… or a double-click on the title) now also renames, once, the Claude Code or Codex session in it. hrdrhrdrhrdr submits the agent's own `/rename <name>`, only while the agent is idle or done and nothing is typed in its input box. Otherwise the rename waits and goes when the agent is ready. A newer rename replaces it, and it is dropped when the pane closes, another session takes its place, or hrdrhrdrhrdr quits. This works on This Mac, on an SSH machine added in Settings and on a herdr machine. The `/rename` line stays in the agent's terminal and input history.
- A Pi opened from the new tab launcher gets the name through hrdrhrdrhrdr's Pi extension while it is idle; nothing is typed. A Pi started from the shell is not renamed.
- Removing a pane's name, renaming a tab, and renames made in herdr itself leave session names as they are.

## New tab launcher

- While you name the tab in the new tab launcher, Tab picks the next program to open: Shell, Claude Code, Codex, Pi, then Shell again. ⇧Tab picks the previous one. The insertion point stays in the name field, and what you typed stays as it is. Clicking a Launch choice still works.
- Where the launcher shows no Launch choices, or shows them greyed out (a tab on a herdr machine opens a shell only), Tab does nothing.

## Renaming in the window's title

- While you type a new name in the window's title, the Show Browser and Show Preview buttons stay at the right end of the toolbar. Before, they moved left, next to the name field.
- In the name field, the insertion point, the name and the grey placeholder now start 12 points in from the field's rounded left end, instead of 6.
- A double-click on the title's text renames the pane or tab selected in the sidebar, as Rename in that row's menu does. The window does not zoom.
- A double-click elsewhere in the toolbar still does what System Settings sets under Desktop & Dock, "Double-click a window's title bar to": zoom or minimize. A double-click on the title does the same when nothing can be renamed: when no pane or tab is selected, or when something such as Settings covers the terminal.

## Other changes

- In Pi, ⌘← and ⌘→ move to the start and end of the line. They are sent as the Home and End keys to a program that has turned on the kitty keyboard protocol, as Pi does. In a shell they do what they did before.
- The browser globe beside an agent in the sidebar stays green while that agent runs, even after its browser connection rests for ten minutes without a tool call.

## Fixes

- Launching Claude Code, Codex or Pi from the new tab launcher sometimes failed with "hrdrhrdrhrdr agent runtime rejected the operation (setup-busy)". The new pane was kept, but the agent did not start.
- The cause: only one task at a time may change the agent runtime's files, and it holds a lock while it does. hrdrhrdrhrdr checks new panes every two seconds, and that check takes the lock too. When the check took the lock first, the launch gave up at once. Now, when the lock is taken, a launch or a resume asks for it again every 0.1 seconds, for up to 5 seconds, and fails with "setup-busy" only after that.
- A lock left behind by a task that crashed or was killed no longer makes every launch fail with "setup-busy" until it is removed by hand. The lock is now released when the task's process ends, however it ends, and the next task cleans up after it. When the lock can't be taken for another reason, launches fail with "runtime-lock-failed" instead.

## Known issues

- Agent sessions started before this update keep using the agent runtime of the version that started them. If one of them leaves its lock behind, launches and resumes fail with "setup-busy" after 5 seconds until the Mac restarts.
- After you go back to 0.5.2 or an earlier version, launches can fail with "setup-busy" until you delete the file `.lock` in `~/Library/Application Support/com.bldg-7.shepherd/AgentRuntime`.
- With herdr older than 0.9.0 on the machine a pane is on, a plain drag there still selects nothing. Use ⇧-drag.
- The sidebar can lag behind herdr, so an ID dragged right after a pane was moved or closed can be out of date.
- After a QR code has been shown, the Settings window stays out of screen captures and screen sharing until it is closed.
- If a device disconnects after the Mac has started to add its key, the key's line and the device stay; remove the device from the list in Settings → iPhone and iPad.
- The browser engine keeps the key it encrypts cookies with in a Keychain item named "Chromium Safe Storage". If another app made an item with that name first, starting In-app Browser shows a Keychain prompt for it. Allow lets the browser read its saved logins this time, and the prompt comes back the next time the browser starts. Always Allow also lets the browser read them, and the prompt does not come back. Deny leaves the browser unable to read its saved logins, and the browser drops them.
- In a narrow window, the name field for renaming in the title can move into the toolbar's overflow menu (»), and a name cannot be typed. Make the window wider before renaming.

## Compatibility and scope

- Universal macOS app (Apple silicon and Intel); macOS 26.6.2 or newer. In-app Browser needs Apple silicon.
- In-app Browser and Terminal File Drop remain experimental and off by default.
- Adding, checking again and removing herdr machines needs herdr 0.9.0 or later on the host.
- Adding a Mac from the iPhone and iPad app needs Remote Login on and herdr running on the Mac.
- The Markdown preview remains inert: nothing in a document is executed or fetched.
