# hrdrhrdrhrdr 0.8.1

macOS release, build 36.

This update keeps the In-app Browser's agent tools from using memory in agents that never open the browser, and reports a failed browser call to the agent as an error it can respond to.

## In-app Browser tools for agents

The In-app Browser tools reach an agent through two processes: a small connector process that the agent talks to, and the browser tool server (Playwright MCP) that operates the browser.

- **Started on first use**: in Claude Code, Codex and Pi tabs started from New Tab, only the connector runs until the agent makes its first browser call. That call starts the browser tool server, so it takes a little longer than later calls. Before, the browser tool server ran from the moment the agent started: two processes for Claude Code and Codex, three for Pi.
- **Results that are too large**: if a browser call's result is over about 8 MB, such as a very large full-page screenshot, the agent gets an error saying the result was too large, with a suggestion to save it to a file or ask for a smaller part of the page. The browser keeps its open page and state. Before, such a result ended Pi's browser tools until a new tab was started, and Claude Code and Codex received the whole result.
- **When the browser tool server stops**: calls that were waiting for it get an error saying the browser server stopped and the call can be retried. The next browser call starts the server again.
- **Pi readiness**: for Pi, the sidebar shows the In-app Browser as ready once Pi has connected to the connector process. It no longer waits for the browser tool server to start.
- **Agents already running**: agents started before this update keep the previous browser tools until their tab is started again.

## Requirements

Universal macOS app for Apple silicon and Intel; macOS 26.6.2 or newer. In-app Browser requires Apple silicon. Experimental features remain opt-in.
