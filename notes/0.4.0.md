# Shepherd 0.4.0

macOS release, build 28. Includes the updates implemented since 0.3.3.

**Updating from 0.3.3: close Settings before you choose Install and Relaunch.** While Settings is open, 0.3.3 can't quit, so Install and Relaunch only beeps and Shepherd keeps running. If you checked for the update with Check Now in Settings, Settings is still open behind the update window. From 0.4.0 on, an open Settings no longer stops an update.

In short: Shepherd shows a macOS notification when an agent on any of your machines needs your input or has finished, also with its window closed. The sidebar shows new terminal titles, panes and tabs within about a second. Tabs and panes are renamed in the window's title instead of a dialog. ⌘⌫ deletes to the start of the line. Terminals don't draw while the window can't be seen, and Shepherd Browser's checks cost less. A crash in 0.3.3 is fixed.

## Notifications

- Shepherd shows a macOS notification when an agent needs your input or has finished. Needing input is herdr reporting the agent as Blocked. Finishing is an agent going from Working or Blocked to Idle or Done.
- It watches every machine in Settings, the active one and the others, and the herdr machines under them. It does so from launch to quit, with its window closed too. For this, it keeps a connection open to each machine, over SSH for remote ones.
- The title names the agent and what happened, such as "claude needs your input" or "claude finished". The body is the pane's title and its workspace. With more than one machine in Settings, or on a herdr machine, the machine's name is shown too. A new notification for a pane takes the place of the one before it.
- Clicking a notification brings Shepherd's window up, opening it again if it was closed. It makes the pane's machine the active one and selects the pane, or its tab with Group by Tab on.
- A notification is removed from Notification Center once you look at the pane, or when the agent goes back to work.
- There is no notification for the pane you are looking at: the selected pane, or any pane of the selected tab, while Shepherd's window is active. There is none for a status that doesn't last 1.5 seconds, and no second one of the same kind for the same pane within 10 seconds. An agent that finishes within 10 seconds of first being seen is only starting up, and gets none. Changes made before Shepherd connected to a machine, or while it couldn't reach the machine for over a minute, get no notification.
- herdr decides when an agent is waiting. A prompt herdr doesn't recognize gets no notification.
- A notification usually comes about 2 seconds after the status changes. herdr machines are read every 5 seconds, so theirs can take up to 5 seconds longer.
- Settings has a new Notifications page, above Experimental Features. It shows whether macOS allows Shepherd's notifications, with Allow Notifications… or Open System Settings to change that. If you haven't answered macOS yet, it asks when the first notification is due.
- Under Notify Me When, "An agent is waiting for your input" and "An agent has finished" turn each kind on or off. Both are on to begin with. With both off, or with Shepherd's notifications turned off in macOS, Shepherd stops watching the machines the window doesn't show.
- herdr's own notifications come only from herdr's own interface, open in a terminal app. Shepherd doesn't show them. If herdr's interface is open in a terminal app, you may get both. To keep only Shepherd's, set `delivery = "off"` under `[ui.toast]` in herdr's `config.toml`. Shepherd doesn't read or change herdr's settings.

## Sidebar

- On this Mac and on machines reached over SSH, the sidebar shows these within about a second: a terminal's new title, a pane, tab or workspace opened or closed, a tab or workspace renamed, and a tab split differently. They took up to 25 seconds before, or 5 seconds on a machine with no agent. Shepherd now subscribes to herdr's events. It used to wait only for agents' status to change.
- herdr machines are still read every 5 seconds. A pane renamed in herdr itself, and a changed working directory, still take up to 25 seconds: herdr reports no event for them.
- A herdr that doesn't accept the subscription is read as in 0.3.3. herdr 0.9.0 and 0.9.1 accept it.
- With notifications on, switching to another machine shows its panes at once, without "Loading panes…".

## Renaming tabs and panes

- Rename Tab… and Rename Pane… in the sidebar's context menu no longer open a dialog. The window's title becomes a field with the current name selected, and you type the new name there. The row is selected first if it isn't.
- Return saves the name. Escape cancels. Clicking elsewhere, or selecting another row, saves what has been typed. After Return or Escape, the keyboard goes back to where it was.
- For a pane you haven't named, the field starts empty, with the pane's automatic title shown in grey. Saving an empty name removes the name you gave the pane, and the pane shows its automatic title again, as before.
- A tab can't be left without a name. Return on an empty name beeps, and leaving the field empty keeps the old name.
- The title shows the new name at once, before herdr reports it.
- While an input method is composing, as for Korean or Japanese, Return and Escape go to the input method. The syllable being composed is kept in the name.
- ⌘W does nothing while a name is being typed.

## Terminal

- ⌘⌫ and ⇧⌘⌫ send Ctrl-U to the program, which deletes back to the start of the line in a shell and in Claude Code's prompt, as in Ghostty and iTerm2. Before, these keys did nothing.

## Energy use

- While Shepherd's window can't be seen, terminals don't draw. That is when the window is covered by other windows, on another Space or minimized, or Shepherd is hidden. Terminals still take in all of their output, and each is drawn once in full when the window can be seen again. The terminal keeps keyboard focus.
- With Shepherd Browser on, the check of this Mac's panes every two seconds costs less. It no longer starts a shell and Node each time. It asks herdr for an agent pane's processes only when herdr reports a change in that pane, or 30 seconds after it last asked.
- When registering a pane for the browser fails, or preparing the agent in a pane fails, Shepherd waits before trying that pane again: 30 seconds, then 60, 120 and 240, then every 5 minutes. It used to try every two seconds. Diagnostics keeps showing the error meanwhile. Retry Preparation, Check Prerequisites Again, saving the settings and changing the port try again at once.

## Settings

- Experimental Features shows two cards: Shepherd Browser and Terminal File Drop. Password Manager, Preparation, Advanced and, when there is an issue, Diagnostics are rows of the Shepherd Browser card instead of sections of their own.
- The settings are named Shepherd Browser and Terminal File Drop, without "(Experimental)". The sidebar menu's Resume with Shepherd Browser (Experimental) is now Resume with Shepherd Browser. Both features are still experimental and OFF by default.
- Clicking an ⓘ opens its explanation in a popover. A click outside it, or Escape, closes it. Hovering still shows the explanation as a tooltip.

## Fixes

- Shepherd 0.3.3 could crash while it showed a machine with herdr machines. In the release build, the Swift compiler mishandled the code that reads all herdr machines at once (swiftlang/swift#92698). That code is now written in a way the compiler handles correctly.
- With Settings or Go to Agent or Pane… open, ⌘Q and an update's Install and Relaunch only beeped, and Shepherd didn't quit. Now the open one closes and Shepherd quits. When browser agents are connected, Shepherd still asks first, as before.
- With Block other browser tools on, choosing Pi in the new tab launcher failed with `pi-tool-policy-unqualified`. Pi now launches. The setting isn't applied to Pi: Pi keeps all of its MCP servers. The setting's help text in Settings says so.
- In the new tab launcher, a syllable being composed, as with a Korean input method, disappeared when the launcher was redrawn. That happened when the pointer moved over the list, or when the sidebar updated. It now stays in the field.
- Typing in "Browser MCP servers to block" registered every pane again at each keystroke, running Node for each pane. Shepherd now registers each pane again once the browser settings have stayed the same for a second. A pane whose registration was running while the field changed could keep the earlier value. It now gets the latest.

## Internal

- Notifications are made from agent events with a fixed JSON form, so that programs other than Shepherd on the Mac can produce the same events later. The example events in `Tests/Notifications/agent-events` are the reference.
- A test builds the code that reads herdr machines with optimization (`-O`), as a release build does, and fails on the miscompile that crashed 0.3.3.

## Compatibility and scope

- Universal macOS app (Apple silicon and Intel); macOS 26.6.2 or newer. Shepherd Browser needs Apple silicon: the browser engine Shepherd embeds (CEF) is built for Apple silicon only. On an Intel Mac, Shepherd runs without it.
- Shepherd Browser and Terminal File Drop remain experimental and OFF by default. The browser's scope is unchanged from 0.3.3, apart from Pi launching with Block other browser tools on.
- Notifications are on by default. macOS asks before the first one is shown.
- The Markdown preview remains inert: nothing in a document is executed or fetched. The file preview's limits are unchanged from 0.3.3.

Checks made for this release: the tests for the changes above pass on this source. The app is built, signed and notarized by the repository's release workflow on a GitHub-hosted runner. The checks do not operate the installed app's interface, show a notification or go through an automatic update.
