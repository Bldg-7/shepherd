# hrdrhrdrhrdr 0.5.2

macOS release, build 31. Fixes agent launches that failed with "setup-busy", and improves renaming in the window's title.

In short: launching Claude Code, Codex or Pi from the new tab launcher no longer fails now and then with "setup-busy". While you type a new name in the window's title, the toolbar buttons stay where they are, and a double-click on the title starts a rename.

## Fixes

- Launching Claude Code, Codex or Pi from the new tab launcher sometimes failed with "hrdrhrdrhrdr agent runtime rejected the operation (setup-busy)". The new pane was kept, but the agent did not start.
- The cause: only one task at a time may change the agent runtime's files, and it holds a lock while it does. hrdrhrdrhrdr checks new panes every two seconds, and that check takes the lock too. When the check took the lock first, the launch gave up at once.
- Now, when the lock is taken, the launch asks for it again every 0.1 seconds, for up to 5 seconds. It fails with "setup-busy" only after that. Resuming an agent waits for the lock the same way.

## Renaming in the title

- While you type a new name in the window's title, the Show Browser and Show Preview buttons stay at the right end of the toolbar. Before, they moved left, next to the name field.
- In the name field, the insertion point, the name and the grey placeholder now start 12 points in from the field's rounded left end, instead of 6.
- A double-click on the title's text renames the pane or tab selected in the sidebar, as Rename in that row's menu does. The window does not zoom.
- A double-click elsewhere in the toolbar still does what System Settings sets under Desktop & Dock, "Double-click a window's title bar to": zoom or minimize. A double-click on the title does the same when nothing can be renamed: when no pane or tab is selected, or when something such as Settings covers the terminal.

## Known issues

- The browser engine keeps the key it encrypts cookies with in a Keychain item named "Chromium Safe Storage". If another app made an item with that name first, starting hrdrhrdrhrdr Browser shows a Keychain prompt for it.
- Allow lets the browser read its saved logins this time, and the prompt comes back the next time the browser starts. Always Allow also lets the browser read them, and the prompt does not come back. Deny leaves the browser unable to read its saved logins, and the browser drops them.
- In a narrow window, the name field can move into the toolbar's overflow menu (»), and a name cannot be typed. Make the window wider before renaming.

## Compatibility and scope

- The Macs hrdrhrdrhrdr runs on, and the scope of its experimental features, are unchanged from 0.5.1.

Checks made for this release: the tests for the launch fix and for renaming in the title pass on the source this release is built from. The app is built, signed and notarized by the repository's release workflow on a GitHub-hosted runner. No check was made in the installed app: none launched an agent or double-clicked the title there, and none installed this release through an automatic update.
